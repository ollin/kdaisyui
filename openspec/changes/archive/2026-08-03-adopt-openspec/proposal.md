## Why

`openspec init` just wrote ~30 files into the working tree — `openspec/`, six OpenCode
skills, `.github/prompts/`, `.github/skills/` — and every one of them is untracked. They are
the project's planning workflow: uncommitted, they are invisible to any other contributor and
gone on a clean checkout.

At the same time OpenSpec 1.7.0 ships three configuration hooks that this project needs and
currently leaves entirely commented out (openspec/config.yaml#L3-L32):

- `context` — project background served to whoever writes an artifact,
- `rules` — per-artifact constraints,
- `operations.apply|archive.guidance` — advisory guidance delivered exactly when
  implementation or archival starts.

Without them, the working agreements that actually govern this repo — one Arlo commit per
task, the full verification gate including e2e, evaluation under `./tmp`, archive-before-MR —
live only in a machine-local agent skill. A second contributor, human or agent, does not
receive them. The knowledge is real but unshared, which is the same as absent.

Doing this first means the three following changes (`commit-generated-sources`,
`codegen-to-kotlin`, `drop-llms-txt-ceiling`, `daisyui-taxonomy-api`) are planned and
implemented under rules the repository itself states.

## What Changes

- **Commit the OpenSpec scaffold**: `openspec/config.yaml`, `openspec/specs/`,
  `openspec/changes/` and the six `.opencode/skills/openspec-*` skills.
- **Fill `openspec/config.yaml`**, replacing the shipped comment block with real content:
  - `context`: the facts an artifact author must not get wrong — generated versus hand-written
    source, the `io.github.ollin.kdaisyui` package, `gradle.properties` as the single version
    source, the four-module layout, and the fact that there is no release automation.
  - `rules`: per-artifact constraints, notably that `tasks` must be sized so each task is one
    Arlo commit.
  - `operations.apply.guidance` and `operations.archive.guidance`: the definition of green
    (repo-wide compile, complete suite *including* e2e, coverage, CodeScene change-set scan),
    the commit-after-every-task cadence, and archive-on-the-implementation-branch.
- **Remove the GitHub Copilot integration**: Copilot is no longer used, so
  `.github/copilot-instructions.md` is deleted and the `.github/prompts/` + `.github/skills/`
  directories that `openspec init` created for it are never committed. The uncommitted
  `README.md` edit already drops the corresponding row and stands as written.
- **Record `skip_specs: true`** in the contributor documentation: new in 1.7.0, it lets a pure
  refactor, tooling or docs change pass validate and archive without inventing a requirement.
  This change is itself the first user of it.

No production code is touched. No public API changes.

## Capabilities

### New Capabilities

None. This change adds no system behavior — it commits planning tooling and project
documentation. `.openspec.yaml` therefore declares `skip_specs: true`, which is precisely the
case that flag was introduced for. Inventing a requirement here to satisfy validation would
put a false statement into `openspec/specs/`.

### Modified Capabilities

None.

## Impact

**Committed as-is (generated by the CLI, not authored here)**
- `.opencode/skills/openspec-{propose,apply-change,update-change,sync-specs,archive-change,explore}/`
- `openspec/specs/`, `openspec/changes/`

**Deleted**
- `.github/copilot-instructions.md`, `.github/prompts/`, `.github/skills/`

**Authored**
- `openspec/config.yaml` — the three hooks.
- `AGENTS.md` — a pointer to the OpenSpec workflow, so the repo's own agent guide names it.

**Prerequisite check**
- OpenSpec ≥ 1.7.0 is required: `skip_specs` and the `operations` block do not exist before
  it. The scaffold on disk contains both, which is the evidence that the installed CLI
  qualifies.

**Deliberately out of scope**
- The global `openspec-house-rules` agent skill lives outside this repository. This change
  moves the *project-specific* part of those rules into `config.yaml`; trimming the global
  skill to only what is genuinely machine-wide is a separate, non-repository task.
