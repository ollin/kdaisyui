### Defect 1 — duplicated dependency entries

Every Renovate bump appears twice, once as the squashed merge commit carrying the PR number and
once as the raw commit:

```
- 0034960 **deps**: Update dependency js-yaml to v5.3.0 (#230), closes #230
- 3a5b3f8 **deps**: Update dependency js-yaml to v5.3.0
```

This is what tempts a reader toward `skipMergeCommits = true` — the cure that would delete
`30b991d`, the one entry worth having. Task 2.5 exists to head that off.

### Defect 2 — the mangled breaking-change note

`30b991d`'s entry runs from line 4 to line 9. The commit body's `BREAKING CHANGE:` footer
absorbs everything after it, including a paragraph that has nothing to do with the breaking
change:

```
- 30b991d 🚨 commit generated sources, adopt DaisyUI 5.7.16, and gate regeneration drift - *TooltipVariant.Neutral is removed; DaisyUI dropped
tooltip-neutral. See "How to migrate" in README.md, which also covers
positional arguments shifting as generated signatures gain modifiers.

Four OpenSpec changes: commit-generated-sources, cleanup-dead-code,
rejoin-main, adapt-daisyui-5-6.*
```

The "Four OpenSpec changes" paragraph was never meant to be part of the migration note. Per the
Conventional Commits spec the footer runs to the end of the body, so this is not a JReleaser
defect and no configuration fixes it — it is a commit-authoring rule, which is why section 3
records it in the two skills instead of trying to configure it away.
