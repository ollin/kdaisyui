Users of the library can now let their users choose a DaisyUI theme with
the compiler's help, and the example app shows the whole pattern on its
profile page.

## What changes
- **`DaisyTheme`** (new package `io.github.ollin.kdaisyui.themes`): one
entry per built-in DaisyUI theme (35), generated by `just generate` from
`daisyui/packages/daisyui/src/themes`.
- **`Tag.daisyTheme(theme)`** writes `data-theme`;
**`daisyThemeOf(value)`** reads a stored value back, `null` for anything
else.
- **`daisyThemeController(theme = DaisyTheme.Dark)`** writes the input's
`value`. Source-compatible; the JVM signature changed, so code compiled
against 0.10.x recompiles (docs/upgrading.md, "How to migrate from
0.10.x").
- **Example app**: `/profile` in the dashboard's frame (sidebar, header,
avatar menu → Profile): an "Appearance" card with a tile per theme, each
a mock-up in its own colours; Save keeps the choice in a cookie, the
pages render `<html data-theme>` from it; "System default" deletes it;
anything else answers 400. No script, strict CSP unchanged. The
stylesheet compiles `themes: all` (150 → 186 KB minified).
- **Docs**: how-to "Let users choose a theme" (compiled snippets),
llms.txt / llms-full.txt, AGENTS.md, kdaisyui-codegen skill.
- OpenSpec change `select-a-theme-in-the-profile`, archived in this PR;
new spec `theme-selection`.
